## Why multi-app is held

The parallel session is collapsing per-app Supabase stacks into **one Supabase per box**,
each app owning a Postgres schema. That deletes a central part of the multi-app plan.
Do not build the `SB_HOST` plumbing — it is being removed.

**Deleted by that decision:** `SB_HOST_<NAME>` keys, carry-forward from each app's own
stack `.env`, the per-app `stack:{kong_port,email_enabled}` manifest block, per-app
`20-install-app-stack.sh`.

**Survives unchanged:** the app-name filter, `IMAGE_TARBALL_<NAME>`, per-app `server.env`,
the app-bridge check, removing the `APP_COUNT>1` guard, `NODE_OPTIONS` default in 23.

**Survives, re-aimed:** the per-iteration-locals fix. The bug was never about hosts — it is
that per-app values resolved with shared variables leak from app 0 into app 1.
`IMAGE_TARBALL_<NAME>` survives, and a leaked tarball installs **the wrong application**
under the second app's name and port, passing its own health check.

**Next move:** wait for the data-architecture spec, then rewrite the multi-app spec against
it. It should come out materially smaller.

## Landmines found the hard way — do not rediscover these

- **`NODE_OPTIONS=--max-http-header-size=65536`** is required for every Node tile app or
  SSO fails with HTTP 431 and the tile renders **blank with no client-side error**. Pop Bys
  has carried it by hand since install; `grep -rn NODE_OPTIONS scripts/ templates/` returns
  nothing. Verify with a **20KB** cookie — a 9KB one is under Node's 16K default and proves
  nothing.
- **Script 25 bridges are not optional.** Script 23 binds apps to `127.0.0.1` only; the
  dashboard reaches them over `172.17.0.1`. Missing bridge = 502 while every loopback health
  check passes. Two are needed per app: `<name>:<app_port>` and `<name>-sb:<kong_port>`.
- **Script 22 renders the Caddyfile from ONLY its args.** Pass the box's full vhost set or
  you silently delete the others.
- **Probes lie.** Three times in one session: a spike that passed because it probed the one
  dynamic route while four static routes were frozen; a `wget` test that "failed" because
  `node:20-slim` has no `wget`; a 9KB cookie that passed under a 16K limit. Before trusting
  a passing probe, show it failing for the reason it is meant to catch.
- **A 1006 / "missing Sec-WebSocket-Key" is usually header SIZE, not Cloudflare.** Count the
  `*.jnow.io` Supabase auth-token cookies first; it costs a minute. My 2026-07-27 OB1
  capture blamed Cloudflare and is corrected — read the correction, not just the original.
